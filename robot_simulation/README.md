# 视觉割草机器人控制台

四轮后驱割草机器人仿真系统：以 **100° FOV / 1 m 视觉深度传感器**为主要感知，完成自动建图、自动分区、自动割草（沿边 + 弓字全覆盖 + 绕障）、自动回充与断点续作，并通过浏览器界面实时展示地图、覆盖情况、视觉视场和任务状态。

后端零第三方依赖，要求 Python 3.8+。

## 快速开始

```bash
cd robot_simulation
./run.sh                 # 默认 http://127.0.0.1:8000/
# 或指定地址与端口
HOST=0.0.0.0 PORT=9000 ./run.sh
# 也可以直接运行
python3 backend/app_launcher.py --host 127.0.0.1 --port 8000
```

如果 `./run.sh` 报 `OSError: [Errno 98] Address already in use`，说明 8000 端口上还有一个没退出的旧进程：

```bash
ss -ltnp | grep :8000     # 找到 users:(("python3",pid=12345,fd=3)) 里的 pid
kill 12345                # 再重新运行 ./run.sh
```

打开 <http://127.0.0.1:8000/>：

1. 在顶部 **地图** 下拉框选择 1–5 号场地（切换会重建机器人与地图）。
2. 点击 **自动建图**，机器人驶向边界并逆时针巡边；完成后自动分区并返回充电桩。
3. 在 **割草区域** 输入顺序（留空时自动使用全部区域，如 `1,2,4,5`），点击 **开始割草**。
4. 需要中途补电时点击 **立即回充**；充好电后点击 **继续任务**，机器人会先回到断点再继续。
5. 仿真速度支持 1x / 2x / 4x / 8x / 16x / 32x，便于快速演示完整任务。
6. 侧栏 **地图** 面板里点 **自动导入**（扫描服务端 `data/map` 下所有含 `.pgm` 的地图并一次性导入），或用“选择文件”上传单张真实 PGM 地图；导入后立即切换为新增的模拟场地。同一面板的 **地图编辑** 可以自己画区域、通道、充电桩、禁区与障碍物，也可以载入一张已有地图改，保存成一张新地图。

## 两种独立仿真应用

顶栏“仿真”下拉用于切换 **内部仿真** 与 **接入导航进程**，默认启动内部仿真。也可以直接启动导航模式：

```bash
./run.sh --tea-bridge --mode nav_process
# 可选：--tea-host 127.0.0.1 --tea-record-port 20015 --tea-map-port 20018
```

- **内部仿真**：保持本节描述的全部功能（控制台、地图导入与地图编辑器、底部日志播放）；业务代码仍在 `backend/server.py`、`frontend/app.js`。
- **接入导航进程**：独立页面 `frontend/nav_process/` 和独立服务 `backend/nav_process/`，使用 `/api/nav/*`；没有日志分析/播放、内部任务或内部地图编辑接口，也不读取内部仿真的障碍与地图状态。
- 两套应用只共用顶栏模式入口和启动器。切换会停止当前任务、回放或遥控，销毁当前应用并在原端口启动另一套应用，随后整页刷新；工作区构建中需先保存或取消。
- 导航模式需要 `pyzmq` / `protobuf`。依赖或 tea 不可用时仍停留在导航页面并显示桥不可用，不会回退成内部仿真。

运行 `./packaging/pack.sh` 后在 `build/tea_sim_dist/` 启动：`./run.sh sim` 仅启动内部仿真，`./run.sh start` 同时启动 tea 和仿真（默认内部仿真）；有 tmux 时可通过 `./run.sh attach` 查看输出。

### 导入真实 PGM 地图

侧栏 **地图** 面板的 **地图导入** 分组（可收起）提供两种真实地图导入方式（界面不再提供服务端路径输入、最大边长设置和目录选择）：

- **自动导入**：调用 `POST /api/map/scan`，扫描服务端仓库 `data/map` 下所有含 `.pgm` 的目录（或 `.pgm` 文件）并一次性全部注册（可用环境变量 `ROBOT_MAP_DIR` 改根目录）。重名地图会自动补上目录名后缀，同一目录重复导入复用原编号、不会重复占号；导入完成后切换到第一张，并在提示里列出全部编号与名称。
- **选择文件**：支持 `.pgm`（必需），以及 `default.json`、`map_info.json`、`.yaml/.yml`（可选）；`default.json` 会自动放到 `path/default.json`。

浏览器选择文件时使用 `POST /api/map/upload` 上传，服务端只接受 `.pgm/.json/.yaml/.yml`，单文件最大 16 MB，单次总量最大 24 MB；未指定时地图按默认 24 m 最大边长等比缩放。服务端仍保留 `POST /api/map/import`（服务端路径导入）供脚本/测试使用。

- 解析 `default.json` 的 `resolution`，读取 P5/P2 PGM，提取最大连通自由区的外轮廓和内部障碍孔洞。
- 地图会等比缩放到 `max_extent`（默认 24 m，避免真实几十米场地在仿真中过大），并自动生成充电桩/起点。
- 导入地图会加入地图下拉框（编号从 101 开始）；同一来源重复导入会覆盖原编号。界面会把真实障碍轮廓画成实线，视觉聚类结果仍以虚线显示。
- 地图下拉框旁提供“删除地图”按钮，仅删除导入地图与自建地图；删除当前地图后自动切回 1 号内置场地。内置地图不可删除。

### 地图编辑器（自建地图 / 改已有地图）

侧栏 **地图** 面板的 **地图编辑** 分组是一套可视化地图编辑器，和地图导入**并列**，两块都能单独收起，且**只在没有任务运行时可用**（建图、割草期间接口直接返回 400，界面按钮置灰）。编辑期的所有几何都存在草稿里，**不影响当前地图**，只有点“保存地图”才会生成一张新地图（编号从 101 起，编号与名称出现在顶部地图下拉框，标注“· 自建”）。

- **界面分三段**：“载入 / 保存”、“区域 / 通道”、“元素 + 画笔参数”，按钮按功能分栏排布，常用操作一眼能找到。
- **空白地图**：切到一块 **100 × 100 m** 的空场地（坐标为 0–100 m），想画多大画多大；**保存时按实际用到的元素外接框裁剪**（四周留 1.2 m 余量），生成的地图就是元素范围的尺寸，不会是 100 m 见方。进编辑后视图自动取景到小车周围 ~32 m，画出来的东西立刻能看清（不再整张 100 m 缩成一小块）。
- **选择地图 + 载入编辑**：下拉框列出已有地图（内置 / 导入 / 自建），**默认选中第一张、没有“不选”项**（要画新图就点“空白地图”）；选中后点“载入编辑”把它的场地轮廓、障碍物、充电桩、禁区、动态障碍和通道读进草稿，**并整体挪到 100 × 100 m 画布正中**；改完保存为**新**地图，原图不受影响。载入时会按 `world.MAP_SCALE` 换算坐标，保存出来的尺寸和原图一致。
- **地图名称**：编辑区顶部的“地图名称”输入框就是保存时用的名字，可随时改。
- **撤销**：每次编辑（增删元素、改路径）前都会存一份几何快照，点“撤销”可以退回去（最多 30 步），删错了不用重画。
- **元素删除**：点按钮后在地图上点区域 / 通道 / 充电桩 / 禁区 / 障碍物即可删除；删除区域会连带删掉挂在它上面的通道。命中顺序为「面元素优先」：禁区 → 障碍物 → 动态障碍 → 充电桩 → 通道 → 区域，避免点在区域内却删不掉里面的东西。
- **添加区域**：点“选择区域起点”后用手动控制把小车沿边界开一圈（前端按 0.12 m 采样位姿画轨迹，画布上实时显示），回到起点附近点“保存区域”。校验：轨迹 ≥ 4 点、首尾距离 ≤ 1.2 m（否则提示“区域未闭合”）、面积 ≥ 2 m²（否则提示“面积小于 2 m²”）；不满足时草稿不变，可继续开小车后再存。“取消区域生成”放弃本次轨迹。
- **添加通道**：点“选择通道起点”后把小车从区域 A 开到区域 B，点“保存通道”。要求两端分别落在**两个不同区域**内部，否则报错。“取消通道生成”放弃本次轨迹。通道是**单行道**（半宽 0.50 m，即 1.0 m 宽）——0.8 m 实测建图会蹭墙进不去，1.0 m 全程 0 碰撞。**通道只用来通行（建图也能开过去）**：它不会把两个区域粘成一个区域，机器人割完一个区域后经通道前往下一个区域。

  **通道压在区域上的那一段照常割草，只有"独属于通道"的部分不割**（`GridMap.apply_passages` 会先看每个格子在不在某个区域多边形里）。界面上两种段颜色不同：区域内的通道段画成淡绿色、纯通道段画成琥珀色，并在纯通道段上标注“通道”（只有一条通道时就是这两个字；有多条时才带编号 `通道 #n`，编号缺失也不会出现 `#undefined`）；栅格里纯通过段落在 `no_mow` 层，不进分区、不计入覆盖率。
- **添加充电桩**：点地图放置，半径由“桩半径”控制。校验：全场最多一个、必须在某个区域内部、离区域边界与已有障碍物 ≥ 半径 + 0.2 m。
- **添加障碍物**：**实心画笔**——按住左键在地图上涂抹，一次落笔就是一条“带宽度的实心带”（不再是若干圆点串起来的圈圈），松手后写入草稿；起点接在上一条笔迹末端时会自动续笔。**显示与保存都只保留外围轮廓**：多条笔迹先刷进 0.1 m 栅格掩膜，再追踪闭合环、Douglas-Peucker 抽稀，重叠/交叉的笔迹合并成一个实心轮廓（`Draft.brush_outlines()`，内部笔触不再一条条留着）；保存时每个轮廓写成一个实体障碍物（视觉可探测、底盘可碰撞），面积小于内部孔洞阈值也不会被丢掉。实测两条交叉笔迹（理论 9.6 m²）合并为**一个 28 顶点、9.5 m²** 的实心块。
- **添加动态障碍 + 设置路径**：点地图放置（半径、巡逻速度取左侧输入框）；路径就在元素列表里每项的“设置路径”按钮上——点一下该障碍物 → 点起点 A → 点终点 B，路径与速度写入草稿（不再单独提供一个“巡逻路径”按钮，避免和列表里的入口重复）。保存后的地图里，动态障碍按这条 A→B 路径以设定速度往返巡逻。
- **添加禁区**：在地图上按住左键拖出矩形（松开即生效，最小 0.4 m × 0.4 m）。
- **保存地图**：校验通过才允许保存——① 至少一个区域；② 有多个区域时全部通过通道连通；③ 至少一个充电桩。不满足时下方红字逐条列出原因。保存成功后自动切换到新地图（`POST /api/editor/save`），草稿关闭；点“退出编辑”则丢弃草稿并切回原地图。
- 编辑器用到的草稿结构、栅格化与校验都在 [robot_simulation/backend/map_editor.py](robot_simulation/backend/map_editor.py)，HTTP 入口见下方 `/api/editor/*`。

### 地图缩放与坐标

- 充电桩默认半径 0.70 m（可通过 `dock_radius` 参数调整），机器人起点会优先选择离场地边界更远的自由栅格。
- 地图支持鼠标滚轮缩放、左键拖动平移、双击复位，也可使用地图左上角的 `＋ / － / ⤢` 按钮。
- 鼠标在地图上移动时显示当前世界坐标（单位 m），便于核对导入地图形状和路径位置。

## 功能说明

### 视觉传感器

- 100° 视场角（±50°），41 束深度射线，量程 1 m。
- 每束光线同时用于避障/沿边控制和占据栅格建图。
- 界面中的蓝色扇面即实时视觉视场，颜色随距离变化。

### 自动建图

- 从当前位置出发，向前行驶直到视觉发现外墙。
- 以 **墙体在右侧** 的沿边控制逆时针绕场一周，视觉持续写入栅格地图（空闲/占据）。
- **孤岛识别**：巡边中若形成面积小于 8 m² 且闭环内部存在已探明占据栅格的闭环，才判定为障碍物孤岛；外凸半岛/顶部尖角造成的路径自接近不会误触发脱离，沿边会继续直到真正的外墙闭环。已识别孤岛会记录并在后续搜索中避开。
- 当闭环面积达到 12 m² 以上、**并且边界已探明 ≥ 85% 且没有还补得上的明显缺口** 才判定建图完成，自动执行自由区漫游与分区，返回充电桩并停靠充电；边界没探明就闭环只算“绕了一圈小区域”，不会误判完成。
- **进度够了立刻收尾**：巡边过程中边界已探明 ≥ **98%** 就直接完成建图（不必再绕回起点），避免“地图已经建完了机器人还在绕”。
- **探明率只统计“能被看到的那半圈墙”**：`world.boundary_cells()` 只保留中心点落在场地内的边界栅格。射线永远命中墙面内侧，边界线外侧那一圈格子不可能被写入；把它们算进分母会让探明率永远差一半，还会让补扫去追永远补不上的“缺口”（这是“建图没建完就结束/建图完了还在建图”的根因）。
- **墙体画在场地外轮廓线之外**：感知识别到墙面时，占据格按 `SURFACE_STAMP_OUTSET`（0.08 m）写到墙的**外侧**，导航/刀盘膨胀仍按墙面真实位置算。这样地图上的墙体带落在外轮廓线外面，墙内侧一格都不吃（以前整条边会向内少 0.1–0.2 m，割草时看着像"贴着边界少割一圈"）。
- **探明认定看墙面邻域**：占据格挪到墙外之后，墙内侧那一格常常还是未知，所以“这段墙探明了”的判据是 `data` 已写 **或** 3×3 邻域里有占据格（`GridMap.unknown_wall_cells()`），探明率才不会永远差最后一格。
- **探明不足不收工**：边界还没探到 85% 就想收尾时（缺口都判断为开不过去），先放开周边 1.6 m 导航膨胀、重新找未探明边界，最多再找 6 轮（`MAP_RECOVER_LIMIT`）；确实找不动了才收尾，并在事件里写明残留长度。
- **最后那一点点墙也要刷上**：以前边界探明 ≥ 98% 就直接回桩，结果总在起步/收尾处留一道没喷涂的口子。现在收尾要同时满足"探明 ≥ 98%"和"残留长缺口 ≤ `MAP_DONE_RESIDUAL`（0.25 m，缺口判定门槛 `MAP_GAP_MAX_RUN` 也从 0.6 m 收到 0.3 m）"；不满足就沿墙**再绕一圈**把最后一段补上（最多 `MAP_CLOSE_MAX_LAPS` 圈）。实测内置 5 图建图结束时边界 **99.6–100%**、**没有任何 ≥ 0.3 m 的缺口**（残留 0 m）。
- **墙面涂抹带宽 0.2 m**：`GridMap.mark_occupied` 用 `SURFACE_STAMP_SPAN = 2` 格（0.2 m）贴着墙外侧画占据带（原来是 3 格 0.3 m），墙内侧一格都不吃可割区，界面上的墙体带也更细、边界更清楚。
- **建图只探边界，不主动扫内部**：默认绕完外墙就收工（内置 5 张图 **140–210 s**、边界 98–99%、碰撞 0），场内障碍等割草时再按视觉发现、就地绕障重规划。
- **边界没探全才兜底开进去**：实景大图的“内部隔墙”也算边界，只绕外轮廓永远探不到（`data/map/map_3` 停在 86%）。所以只有 `boundary_discovery() < MAP_FILL_TRIGGER`（95%）时，才按 `MAP_FILL_SPACING`（0.80 m，横/纵交替）生成未知区扫描线补看；一轮没进展（剩余未知面积下降 < max(2 m², 5%)）就改成“开到大块未知区中心看一眼”，最多 4 轮 / 1800 s。内置图不会触发这一步。
- **补看不顶墙**：扫描线常常正对墙面，因此补看时 `_wall_guard` 视场放宽到 ±65°、制动距离放到 0.36 m，并且“命令前进却 1 s 内位移 < 0.10 m”就直接丢掉这条线换下一条（`MAP_FILL_STALL_SECONDS` / `MAP_FILL_STALL_DISTANCE`），不再边撞边磨。补看不开刀盘，速度单独用 `MAP_FILL_SPEED`（0.80 m/s）。
- **脱困不清空补看队列**：早期 `_resume_after_escape("map_fill")` 会把整张扫描线表清空，一次脱困就白扔十几条线。现在只重置当前线的寻线状态。
- **"开过去看一眼"不重复跑**：兜底的未知块质心点会跳过离自己/已访问点 1 m 以内的（`MAP_FILL_SPOT_RADIUS`），否则会出现“生成→到达→再生成同一点”的死循环。
- **找边界卡住不再无限磨**：`map_seek`/`map_escape` 之前完全没有卡滞判定——实景图里机器人能在墙角顶 40 分钟（4000 s 只走了 130 m、碰撞上千次）。现在它们也纳入进度守卫（原地来回转不算进展），卡住先沿历史轨迹后退出小区域，连续 `MAP_SEEK_STUCK_LIMIT`（3）次仍无进展就结束建图回桩；另外还有两道保险：边界进度 `MAP_NO_PROGRESS_LIMIT`（240 s）不涨、或建图累计活动时间超过 `MAP_ACTIVE_TIME_LIMIT`（1500 s，不含充电/回桩）都会收工，并在事件里写明探明率。
- **回充断点恢复补齐建图子状态**：`_restore_breakpoint()` 原来只认 `map_seek/map_follow/map_escape`，建图兜底扫描（`map_fill`）回充回来后找不到分支，会直接掉成 `idle` —— 表现就是"回充一次建图就再也不动了"。现在补上 `map_fill`（连扫描队列、轮次、已扫面积一起存/恢复，回来接着扫），其它 `map*` 子状态也统一回落到 `map_seek`。
- **效果**：内置 5 图不触发兜底（建图 141–211 s、边界 98.8–100%）；`data/map/map_3`（38.9 × 40.4 m 实景图）触发兜底后边界 **86% → 100%**；最难的 `data/map/map_4`（长死胡同 + 回充 4 次）在建图活动 1070 s 后以 **88%** 结束并正常分区，不再挂死。

- **先回桩、到桩再分区**：建图完成后只标记“建图完成”并回桩，停稳在充电桩上之后才做自由区漫游 + 分区（`_partition_after_docking`）。界面上的区域划分出现在机器回到桩之后。
- **缺口补扫**（`_mapping_complete_enough`）：`GridMap.boundary_gaps()` 把未探明的墙格聚成缺口，跨度 ≥ 1 m 的都要处理 —— 先用 `plan_near` 判断“从当前位置能不能开到缺口附近 1.2 m 内”（车体脚下被自己的膨胀糊住时先放开脚下再问一次），能到就开过去原地扫视 3 s，把这段墙补上再继续。最多补扫 4 次；某处补扫没有让探明率涨 0.5% 就记为“白跑一趟”，2 m 内不再重复跑；白跑 3 次或没有可达缺口时明确收尾，并在事件里写清残留长度（`建图收尾：边界探明 xx%，…（最大残留 x.x m）`），不会永远停在“建图中”。
- **车体压过的格子不可能被写成障碍**：`GridMap._verify_footprint` 每 tick 把车体中心那一格标成“确实能走”，视觉盖章（3×3 抹笔、凸包填充）之后会把它还原成自由格。凸包填充在 1 m 级窄通道里会把通道糊死，机器人把自己的出路封住后就再也规划不出去（实测 map_3 建图从 53% 提升到 94%）。
- **逃离与贴墙都更稳**：实景地图（多边形顶点 > 40）贴墙巡边把前向余量放大到 0.46 m、速度降到 0.55 m/s；找边界直行时用视觉近距保护（< 0.48 m 原地转向、< 0.72 m 减速带转向），把“蹭墙”碰撞从每 5.7 m 一次降到每 37 m 一次。
- **困在小区域自动脱困**（实景多房间地图关键）：巡边若 **30 s 内边界进度没有 ≥ 1% 的增长**，判定困在小区域 —— 记录该区域为孤岛、放开车体周边 1.6 m 导航膨胀（把被视觉膨胀糊死的门口重新打开），切到 `map_seek` 主动去最近的未探明边界（`GridMap.explore_goal` 只在本机栅格上找“紧贴已探明自由区的未知格”）；找不到未探明边界且边界探明 ≥ 85% 就收尾建图。探索模式下即使看到墙也先离开当前小区域，避免又掉回同一个小圈。
- 建图过程中电量低于 **30%**，或低于“回桩预留电量”（见下）时：保存断点 → 回充 → 电量高于 **80%** → 返回断点继续巡边。
- **回桩路线暂时不通时不再停成“待机”**：连续 3 次放开膨胀仍规划不到桩位，就回到断点先继续手上的建图/割草，隔 30 s 再试一次（连续失败按 30→60→120→240 s 退避）。否则一次电量低就再也回不到任务里（实测 map_5 卡在 90.7% 就是这条）。
- 巡边被障碍物/狭窄角卡住时，优先沿最近约 1 m 的历史轨迹倒车脱困，再重新寻找外墙；历史脱困失败才使用远离碰撞方向的脱离策略。
- **建图只做一次**：建图完成后写入完成标记并丢弃巡边进度与巡边断点；之后若回充/继续任务/脱困又把状态恢复到巡边，会直接回桩收尾，不会再次绕场建图（避免“建图→回桩→继续建图”反复循环）。

### 运行性能

- 视觉写入栅格改为按 0.1 m 栅格采样，避免同一栅格被 0.05 m 间隔重复写入。
- 预计算外墙/障碍物线段用于射线检测；区域安全巡边带使用多源 BFS 距离变换，并缓存同一区域的沿边路线。
- 障碍物聚类、边界建图进度按占据数据版本缓存，界面状态刷新只重新编码变化的数据。
- 动态障碍物只刷新圆形占据（`_refresh_dynamic_geometry`），静态障碍轮廓/线段不再每帧重算；`/api/state` 里的场地静态描述（边界、障碍轮廓、地图列表）也做了版本缓存。实测加入动态障碍前后 32x 仿真推进速率基本一致（33.4x vs 33.8x）。
- **A* 时间预算**（解决高倍速下“系统卡住”）：`GridMap.plan/plan_near` 支持 `time_budget`，导航统一用 0.05 s、建图找边界 0.35 s、回桩 0.35 s，并且每个 tick 有 0.10 s 的规划总预算（`TICK_PLAN_BUDGET`）。实景图上单次 A* 可能 0.3–0.7 s，之前一帧里连做几次就会卡住仿真线程；实测最坏 tick 从 **750 ms 降到 180 ms**。
- **建图收尾不再长时间卡顿**：`build_free_area` 原来逐格 `point_in_polygon`（实景图 7 万格 × 332 顶点 ≈ 13 s），改成扫描线栅格化 `world.polygon_mask()`（22 ms，结果逐格一致）+ DFS 用下标代替坐标元组（1.32 s → 0.19 s）、`_component_distances` 内联边界判断，建图完成那一次的卡顿从 **15.7 s 降到 2.3 s**（其中 1.2 s 是分区本身）。
- **碰撞计数不再虚高**：原地转向时位置不变，不再重复记碰撞（之前贴着墙转圈会每 0.6 s 刷一次“碰撞”）。
- **倍速卡顿优化**（内置图单 tick 3.34 ms → 0.63 ms；导入实景图 2.34 ms → 0.89 ms）：
  - 占据/膨胀写入改为**按行切片**（`GridMap._fill_rows`）：原来每次 `mark_occupied` 要逐格写 9×(5×5+5×5) 约 450 格，现在等价地写 3 个方块（覆盖/导航膨胀/割草膨胀），实测 `update_from_scan` 从 1.56 ms/tick 降到 0.13 ms。
  - `world.raycast` 内联线段/圆求交、提前剪枝，41 条射线的扫描从 0.76 ms/tick 降到 0.33 ms。
  - 沿边超时用的路径长度按 `(点数,首点,末点)` 缓存，不再每 tick 求和。
  - **自适应积分步长**：≤4x 用 20 ms、≤16x 用 25 ms、>16x 用 33 ms（实测放大到 40 ms 会让窄走廊频繁撞墙），配合每轮最多 4 步的补帧上限，32x 实测可达 31.6–32.0x（优化前只有约 3x 推进）。
  - 前端在高倍速下每 4 次轮询才取一次栅格位图（`GET /api/state?map=0` 跳过 71 KB 的 occupancy/mowed），地图位图在后端按 `grid.version` 缓存。
  - **线段空间索引**：外墙/障碍物线段按 1.5 m 方格分桶（`world._rebuild_segment_index`），`raycast` 与 `boundary_distance` 只遍历机器人附近桶内的线段。导入实景图外墙有 100+ 段时，单次扫描从 1.65 ms 降到 0.30 ms。
  - 建图闭环判定改用 0.3 m 空间哈希（`_map_hash`）查同位置历史点，不再每 tick 线性扫描整条巡边路径（路径几千点时是主要开销）。
  - 自由区采样内联步进（去掉每条射线每格的函数调用）；`region_manager` 的 OccupancyGrid 发布改为按真实时间 1 s 节流（原来按仿真时间 2 s，32x 下等于每帧发布一次 97k 点栅格）。
  - **仿真节拍改成按需睡眠**：原来每轮固定 `wait(1 ms)`，一轮又只跑一步（33 ms 仿真），32x 档实际只能跑到十几倍。现在只在“攒不够下一步仿真时间”时才按差额精确睡，空闲时 32x 档实测 **31.6x**、16x→16.0x、8x→8.0x、1x→1.0x。
  - **墙面探测增量维护**：`GridMap.unknown_wall_cells()` 原来每 tick 全量扫 `wall_cells` 并做 3×3 邻域判断，332 顶点的实景图上单次 **8.5 ms**（占整 tick 七成）。改成维护"待探明墙格索引集合"：传感器把某格写成已知（或写了占据格）就把该格及邻域从集合里摘掉，复位/换图时重建一次。与全量扫描结果逐格一致（实测 0 差异）。
  - **按格缓存的线段索引**：`world.raycast` / `boundary_distance` 以前每条射线都要查 9 个分桶再做重复去重；现在按 1.5 m 分桶（只入线段真正穿过的桶）并缓存"这一格附近可能命中的线段下标"，每条射线一次字典查表即可。射线结果与暴力求交逐条一致（误差 0）。
  - **大图状态包 gzip**：实景图 `/api/state` 的栅格字符画有 300+ KB，浏览器每次轮询都要传/解析一遍。开启 `Content-Encoding: gzip`（级别 1）后 **350 KB → 6 KB**，且只在客户端声明支持时压缩。
  - **前端高倍速节流**：轮询间隔按倍速分档（4x→80 ms、8x→120 ms、16x+→150 ms），栅格位图 8 次轮询取一次；渲染帧率在 ≥8x 时降到 30 fps。仅这一项就让"浏览器开着 32x 建图"从 9.4x 回到 **22x**。
  - 实测（实景图 map_3，38.9 × 40.4 m，单核）：32x 档浏览器开着跑建图 **10–12x**、关掉浏览器 16–22x；同样场景优化前只有 **2.3x**。内置图 32x 空闲 31.6x。
- 障碍物轮廓在世界切换时预计算，避免每次 `/api/state` 重复计算。

### 自动分区

- 建图完成后先按探明自由区做 **连通域分区**，不再以整张地图的包围盒做 BSP 切分。
- **每次开始割草重置障碍层**：建图完成时记录当时的占据/膨胀栅格作为基线；新割草任务先恢复到该基线，清掉上次割草涂抹出来的障碍（假障碍、草地碎屑误检），场地边界建图与分区轮廓保持不变。
- **地图编辑器画好的区域直接就是割草区域**：编辑器保存的地图会把区域多边形存进定义（`regions`），建图完成后 `partition_zones` 先按这些多边形给自由格分配归属（重叠处归小区域，区域边缘半格按最近区域补齐），**画了几个区域就分几个区域**，哪怕两块在栅格里是连着的（区域边缘相接、只隔一条单行通道）也不会并成一块；这条路上不再做“过小碎片合并”，用户画的小区域不会被吃掉。没有自带区域的地图（内置场地、导入的 PGM 实景图）仍按自由区连通域分区。
- **一个连通自由区就是一个区域**：以前会按凸包实心度判断“形状是否规则”，把哑铃形/细腰地块沿最远点测地线劈成两块，于是在同一片连通草地中间多出一圈沿边路线，既多走路又容易沿到人工分界上。现在只做连通域 + 过小碎片合并两件事（`GridMap.partition_zones`），规则与不规则地块一视同仁。
- **割草按区域逐个走完全流程**：区域顺序里的每一个区域都先沿边、再弓字、再（纵向/漏扫）补割，这个区域真的割完了（覆盖率达标或补割用完）才穿通道去下一个区域，不会在两个区域之间来回跳。
- **纯通道段不参与分区**：通道压在区域上的部分照常计入区域与覆盖率，只有“独属于通道”的格子（`no_mow` 层）既不割草、也不作为区域的连接边，所以“两个区域 + 一条单行通道”的地图仍然是两个区域，机器割完一个再穿通道去下一个。
- 区域栅格**互不重叠**（每个格子只归属一个区域），对外输出 `outline` 实际栅格轮廓，界面按真实轮廓绘制，不再用外接矩形，避免相邻区域看起来重叠；`zone_at()` 只按归属栅格判断，不再用外接矩形回退，覆盖率统计不会串区。
- 所有区域面积不低于 **20 m²**；小于该面积的碎片合并到最近的连通区域。
- 每个区域的 `free`、包围盒和覆盖率会显示在控制台；区域编号按质心从上到下、从左到右排列。

### 自动割草（A / B 两种模式）

- 启动时确认区域顺序（留空则使用全部区域），按顺序前往各区域。
- **区域边界 = 机器人真正能走到的连通区**：`GridMap.build_free_area()` 只沿「场地内 + 非占据 + 无导航膨胀」的格子从车当前位置漫游。以前未知格一律算自由，区域里会混进一堆被膨胀封死的死角 —— 那些死角的弓字起点全是“不可达”，只能一条条跳过，割草永远做不完（这就是“一开始割草就结束”的主因）。导航膨胀同时收紧到 1 圈（`INFLATE_CELLS=1`，车体半径 0.18 m 量级），1 m 宽的走廊不会被自己封死。
- **来回绕的防护**：`_nav_step` 会放过“近在身后（<0.45 m 且偏角 >2.1 rad）够不到”的路点、6 s 内没靠近的路点；原地掉头不再算卡滞，但原地转两整圈（`MAX_SPIN_WITHOUT_MOVE`）或 10 s 内净位移不足 1 m 仍算卡滞。
- **卡住能退出来**：导航/回桩/换区域失败时先 `_start_backtrack()` 沿自己开过的轨迹原路退回 6 m 再重新规划（来路一定走得通）；割草阶段如果 180 s 内净位移不足 1.5 m，直接放弃本区域继续下一个，不会把电耗光停在场地上。
- **绕障（绕障碍物一圈）不再半途而废**：以前弧段一被挡住就跳过几个点、卡滞两次就结束整圈，绕障经常断在半路。现在按四级降级处理（都不放弃这一圈）：
  1. 车被挤到绕障圆**内侧**时，先按半径方向把车推回圆弧（`_ring_nominal_radius` + 径向纠偏），再沿弧走 —— 这是以前"离目标 0.29 m 却原地不动"的直接原因；
  2. 弧段被挡 → 弧段整体外推 + **收紧预瞄**（改瞄离车最近、且直线可达的弧点，弦更短不会切进来），只在连续多次无效时才跳点（`RING_PROBE_LIMIT` = 8）；
  3. 卡滞/超时/擦碰（`RING_BUMP_LIMIT` = 5）→ **换成贴面绕行**继续把这一圈绕完（`_ring_to_surface`，最多 3 次），不再直接判死；
  4. 贴面绕行也走不通才记入"已绕行"并重新规划。
  贴面绕行本身的边界也放宽了（`DETOUR_ZONE_SLACK` 0.35 m、`DETOUR_MAX_DISTANCE` 14 m），障碍物贴着区域边缘时不会一走就"绕障中断"。
  **实测（内置 1/3/5 图 × A/B 六轮整图割草）：绕障 31 次全部绕完（跳障 0 次，改前 11 次中断、其中 1 次直接跳过障碍），碰撞次数与改前一致（0/0/0/1/1/0），覆盖率不变。**
- **沿墙判断只用本区域的作业轨迹**：`zone_history` 只记录本区域内真正作业（沿边/弓字/绕环/绕障）走过的点，区域之间的转场路线（`to_zone`）不进这条轨迹，脱困/回退不会顺着转场路线跑偏。
- **A 模式（默认，先沿边）**：每个区域流程：
  1. 沿区域边缘一周；
  2. 弓字覆盖；
  3. 纵向补割；
  4. 环形补割。
- **B 模式（先弓字）**：每个区域流程：
  1. 先规划弓字覆盖；
  2. 遇到**大型障碍物**：不绕障，直接掉头并重新规划剩余弓字；
  3. 遇到**小型障碍物**：绕障后继续弓字；
  4. 弓字和纵向补割完成后，再沿区域边缘割草一次。
- 控制台顶部可以选择 A/B 模式；模式会随任务保存，回充续作后保持。
- A 模式详细流程：
  1. **沿区域边缘一周**：沿用「区域掩膜 ∩ 建图自由区」的思路，但先做两步修正，否则墙边一整条割不到：
     - 自由区本身已被导航膨胀吃掉 0.2 m 量级（`blocked` 层），直接腐蚀出来的路线天然离墙 0.5 m 上下；所以先 `_grow_into_open()` 沿非占据格外扩 `EDGE_GROW_CELLS`（2 格）**且严格限制在场地多边形内**（不限制会从墙缝扩到场外，路线跑到凹口外）。
     - 腐蚀取轮廓后再用 `_snap_route_to_wall()` 逐点吸附：对离墙 ≤ 0.90 m 的点，沿“最近墙点 → 该点”的射线放到 `ROBOT_RADIUS + EDGE_WALL_CLEARANCE`（0.18 + 0.12 = **0.30 m**）——离远了往里推、离太近往外放；法线方向被挡时朝区域中心退，仍不行就丢掉该点。
     - **实测**（服务端 1x–4x 的 0.02 s 步长，A 模式整图割草）：沿边路线离墙距离中位 0.54 m → **0.30 m**、最远点 4.70 m → 1.41 m（实景 map_4）；内置 1–5 图 0.55 m 墙带割到率全部 **100%**、整图覆盖率 96.1–97.8%、碰撞 0–3 次；实景 map_3 整图覆盖率 93.3% → **94.9%**、碰撞 83 → **20**；“沿边连续受阻 → 跳过剩余边缘”在 map_3/map_4 上 **0 次触发**（贴墙走时车体仍留 0.12 m 余量）。高倍速档步长会放大到 0.033 s，实景窄走廊的结果会有波动（既有特性，见上文倍速一节）。
     - 沿边仍用当前路径段上的 0.30 m 纯跟踪预瞄；外凸半岛/墙体命中不会被误判为场内障碍物，避免跳过整段边缘。
  2. **弓字覆盖**：按 0.30 m 行距对区域内尚未割草的连通部分生成蛇形线段，逐段巡迹；只规划可割草且未割过的连续段。**主方向在进区域时按区域长边定一次**（`_preferred_lane_axis`：宽 ≥ 高走横向、否则走纵向），整个主覆盖阶段都用它——绕障后重规划、弓字起点不可达重规划都不会换方向，同一片地上不会再出现“先竖着排、再横着排”。只有补割（主方向线段用尽后的纵向补割、漏扫补扫、覆盖率补割）才允许换成另一个方向。
  3. **纵向补割**：横向弓字结束后若覆盖率仍不足，生成纵向弓字补割。
  4. **环形补割**：对区域内已发现且未绕行过的障碍物绕行一周，覆盖障碍物周围区域。
- **弓字顺序优化**：所有弓字段按“当前位置 + 航向 + 就近端点”重排；障碍物把一条弓字切成两段时，先完成当前一侧，再前往另一侧，减少来回穿越。
- **漏扫补扫与覆盖率保护**：区域主流程完成后检查未割草连通块；面积约 0.2–9 m² 的漏扫块会生成补扫弓字（或沿长轴扫一遍）。
- **建图只探边界，所以割草要能兜住"后发现的障碍"**：场内障碍第一次看到是在割草途中，弓字线会被切成更多段、绕障后重规划也更频繁。区域收尾时按"还剩多少平方米没割到"决定补割轮次（`COVERAGE_RETRY_MIN_AREA` 1.5 m²、最多 4 轮、每轮至少要多割 0.5 个百分点），而不是只看一个固定的覆盖率门槛。
- **内外直角差异化补扫**：逆时针沿边时，外凸直角由预瞄自然转过，不再执行前进-后退；内凹直角则沿入射方向多前进 `inner_corner_advance`（默认 0.16 m）到尖角后再后退转向，覆盖内直角尖尖处的小块漏扫。沿边速度由 `edge_speed`（默认 0.50 m/s）单独控制，沿边超时按实际路径长度动态计算，回充后不会因旧的 90 s 固定超时直接跳过剩余沿边。
- **区域边界约束**：沿边采用逆时针方向，绕障也按逆时针；绕障路径只使用区域内的连续弧段，触到区域边界时结束绕行并沿区域边缘继续，不会绕到其他区域。
- **沿边绕障续接**：沿边遇到已探明或未聚类的小障碍时，先逆时针绕行；绕完或到达区域边界后，重新选择障碍后的边缘点继续沿边。B 模式的最终沿边不会再因为边缘附近的障碍命中而整段跳过。
- **后退脱困**：沿边/弓字/绕障/前往区域/回桩时若持续 4 s 没有有效位移，机器人会沿最近约 1 m 的历史轨迹倒车脱困，再恢复原阶段；同一区域最多尝试 3 次，避免长时间困在障碍物间。**回桩阶段**（`to_dock` / `charge_go` / `charge_return`）脱困两次仍无效时，会放开机器人周边 0.75 m 的导航膨胀（只清 `blocked`，不动建图占据与刀盘层）再重新规划，避免卡在窄缝里一直原地转向。
- **不可达目标处理**：导航前若目标点被新探明障碍覆盖，会改去当前位置连通域内最近的可达点；弓字段起点被覆盖时自动沿弓字寻找第一个可通行入口，若该端被堵则从线段另一端进入，只有两端都不可达才丢弃该段。若区域沿边入口全部不可达但区域内部仍有可达点，会从该内部点开始清扫剩余可达弓字线；只有整个区域都没有可达入口时才跳过该区域。导航中目标栅格被障碍覆盖会立即重规划，而不是继续顶住或直接结束区域。
- **失败弓字按计划键记录**：不可达/卡住/绕障中断等失败都按规划弓字线 `(起点, 终点)` 记录（而不是实际进入点），所以同一条被堵弓字线不会在每一轮重规划里反复重试，剩余可达弓字线可在同一区域内补完，避免“少一块”。
- **连续不可达自动放开膨胀**：连续 5 次找不到可达目标时，会临时放开起点与目标周边 1.2 m 的障碍膨胀再试，并改走最近可达点，模拟视觉碎片把通道封死的情况。
- **高速显示优化**：仿真速度 ≥4x 时前端状态轮询提升到 50 ms，并同步缩短位姿插值窗口，减少高速下的跳跃/卡帧。
- **A 模式沿边绕障续接**：沿边被障碍物中断并完成绕障后，会选择机器人附近、避开障碍且直线/ A* 可达的边缘点继续大沿边；不会直接跳到弓字阶段。
- **贴边绕障**：绕障半径根据视觉占据栅格沿视线方向的实际外边界自适应，不再固定走理想圆；默认安全余量约 0.34 m（含栅格膨胀约 0.1 m），较上一版缩小，可通过窄通道。
- **视觉盲区花瓣绕障**：小型障碍物绕行中若连续失去视觉接触，机器人会停下并向障碍物方向旋转探明，再继续绕行。
- 巡迹遇障：**只使用视觉建图得到的占据栅格**聚类障碍物，不读取场地真值；拟合出包围圆并按 **估算面积** 分类：面积 ≥ **5 m²** 记为大型（B 模式掉头用），**小于 5 m² 一律视为小型**（绕障 + 花瓣探明）。阈值可在“参数 → 地图 → 大型障碍阈值 (m²)”调整。
- **只涂障碍物真实轮廓，不按包围圆涂抹**（`stamp_footprint`）：早期版本把聚类得到的包围圆整片刷进占栅/刀盘/导航层，障碍物周围会多出一整圈假障碍 —— 半径 0.8 m 的圆实际只有 0.5 m 的地盘，剩下 0.3 m 宽的环永远割不到。现在改成：取聚类中心所在的**占据栅格连通块**，用它的**凸包**代表障碍物轮廓补成实心（视觉看不到的背面与内部空洞一起补上），再沿轮廓外扩 2 格（0.2 m）给车体和刀盘让余量。凸包始终不大于包围圆，所以障碍物附近的窄带能正常割到。
- **聚类半径收敛**：`radius ≤ 0.55 × extent + 0.06`，避免只看到弧段时半径虚高；凸包只包**一个**连通块，不会把旁边另一处障碍或视觉噪点一起包进来。
- 实测（map_1，A 模式整轮）：障碍物周边 0.6 m 环内“可割栅格”从旧实现的 169 格提升到 **1355 格**，其中 77% 真正割到；整图覆盖率同时从 93.8% 提升到 **95.9%**。
- **动态障碍物不参与割草规划**：动态障碍只写入临时导航层 `dyn_blocked`（每 tick 重建，`radius + 0.30 m`），不写占据层、不写刀盘层、不写建图数据（`update_from_scan` 命中动态圆时跳过，避免留下拖影）。因此移动物不会把弓字线规划搅乱（实测线段数从 944 段回落到 346 段），移动物走开后原地仍可正常补割。
- **贴身让行**（`_guard_dynamic`）：动态障碍物进入 `半径 + 车体半径 + 0.34 m` 时机器人先停车让行，让行时间不计入卡滞统计（`_dyn_yield`），移动物走开后再继续任务。动态障碍物自己扫过车体不算碰撞（`world.dynamic_clearance`：只有车体主动更深地撞进去才判碰撞），所以机器人能从重叠位置正常开出来，不会被移动物“卡死”并反复触发碰撞恢复。
- **界面真实边界**：控制台同时绘制场地障碍物的真实轮廓（**白色实线**，外侧加深色描边以便在浅色主题下也清晰）和机器人视觉聚类得到的大小障碍估计（橙/黄色虚线），便于对比感知结果。
- **不二次绕障**：成功绕过（或确认无法绕行）的障碍物会加入已绕行记录；再次遇到同一障碍物时跳过环形动作，直接重新规划路径。该记录在回充/断点续作后仍保留。
- **弓字只铺在"真的开得到"的连通域里**：A 模式绕障绕完一圈后，障碍物内部往往还是**从未被看到**的未知格（凸包/包围圆不往里涂），以前"未知=可割"就会在这些点上生成弓字线，机器人却根本开不进去。现在 `GridMap` 维护一份从车当前位置出发的可达掩膜（`set_reach_seed` + `reach_mask`，按行扫描填充，十万格几十毫秒级）：已探明占据环把障碍物内部封在外面，`cell_mowable()` 一并按它过滤，弓字、补扫、漏扫连通块都不会再往里铺。车若被视觉碎片临时困在小角落（可达区 < 50%），自动并入充电桩所在连通域兜底。
- 环形绕障中擦碰或卡滞不会直接退出：先外推弧段、收紧预瞄、放开周边膨胀继续绕，连续多次仍不行才改用贴面绕行（见上文"绕障不再半途而废"）。
- 覆盖率 = 已割草空闲栅格 / 区域空闲栅格；受车体半径与割草宽度限制，障碍物周围和墙边会保留少量未覆盖。典型覆盖率 85%–96%。
- 地图编辑后的实测（map_1，32x，A 模式整轮）：无编辑 **95.66%**、加 0.5 m 静态障碍 + 0.3 m 动态障碍 **95.48%**（碰撞 0–1 次），两者基本持平；同一场景在收敛膨胀之前分别是 94.80% / 93.20%。
- 一个区域完成后自动前往下一个区域；全部完成后返回充电桩。

任务回到充电桩结束时，事件日志会补两行汇总（`_log_task_summary`）：

- 割草任务：`割草指标 · 总覆盖 97.84%（区域1 97.8%（…/… 格））`

### 自动 / 手动回充与断点续作

- 割草中电量低于 30%：自动保存任务（相位、区域、边缘进度、弓字区域、已绕障碍、断点位姿、沿边已用时间）→ 返回充电桩 → 充到 80% → 返回断点 → 恢复任务。
- **回桩预留电量**（按到桩距离动态判定）：机器人每 tick 记录到充电桩的直线距离（`robot.dock_distance`，界面遥测显示“距充电桩 / 回充预留”），预留电量按 `3% + 距离 × 0.65 %/m × (耗电系数/0.6)` 估算（依据耗电模型 0.5 %/m 再乘 1.25 安全系数，耗电系数改小后预留量等比减少）。电量一旦低于“30%”或“预留电量”中的较大者，就提前保存断点回桩，而不是等 30% 才发现回不去。
- **回程路径三级回退**（`_find_dock_route`）：① A* 正常规划；② 规划不出/偏离过大时沿**历史轨迹原路退回**（`_history_route`，按 0.6 m 采样机器人真实走过的点，一定可通行）；③ 仍不行就按“已探明自由区”规划（忽略导航膨胀，只避开已探明占据格），并把途经膨胀放开、允许路线穿过膨胀带，靠视觉前向保护避障 —— 专门解决“视觉膨胀把门口糊死、机器人被困在小区域回不了桩”。
- 历史轨迹按**距离**记录（每 0.12 m 一点，保留最近 800 点 ≈ 96 m），修复了之前按 tick 位移阈值记录导致低速时轨迹为空、脱困/回程无路可退的问题。
- 回桩阶段持续没有位移（4 s）时同样触发脱困：沿历史轨迹倒车 → 两次无效后放开周边 0.75 m 导航膨胀重规划；连续 3 次仍不可达才放弃，不会把整个任务直接丢掉。
- 默认耗电系数 `battery_drain_factor` 为 **0.2**（改造前基线的 20%），界面“参数 → 机器人实体 → 电源”可直接改；回桩预留电量会随耗电系数等比缩放（基准 0.6 时 0.65 %/m）。
- 机器人原地待机（线速度、角速度均为 0）时，耗电按正常行驶功耗的 **10%** 计（`IDLE_DRAIN_SCALE = 0.1`），停靠充电桩仍按 8 %/s 充电。
- “停止任务”是暂停语义；暂停/回充时间不计入沿边 90 s 超时，继续任务不会因暂停过久而直接结束沿边。
- 控制台点击 **立即回充**：保存任务和割草记录，返回充电桩；**不会**自动恢复，必须点击 **继续任务**。
- 续作前机器人先驶回保存的断点；建图任务还会原地对齐到断点航向，保证继续逆时针巡边。
- 断点保存在当前任务内，切换地图或复位会清除。

### 日志播放（bag 回放）

“底部面板 → 日志播放”可以把历史 rosbag 里记录的真实位姿轨迹映射到仿真机器人上重放，用来复盘真实作业过程：

- **支持的格式**：ROS 2 `rosbag2` 的 sqlite3 存储（`*.bag` / `*.db3`），默认读取仓库根 `data/bag` 目录，可用环境变量 `ROBOT_BAG_DIR` 指定；100 MB 级 bag 解析约 0.5 s（纯标准库 protobuf wire 解析，不需要 `.proto`）。
- **日志文件夹**：`data/bag` 下每个子文件夹当成"一组日志"自动列出（如 `掉下台阶侧翻/`、`自动建图失败，车辆被困/`），面板顶部“日志文件夹”下拉用于筛选；也支持在“导入文件夹”里填服务端绝对路径，把任意目录加进日志根（去重、重启后需重新导入）。
- **只读日志目录**：面板不再需要手动填路径导入文件夹，点“刷新”就会重新扫描 `data/bag`（含其子文件夹分组）；脚本/测试仍可用 `POST /api/bag/dir` 追加其他目录。
- **连续播放**：日志列表左上角有 **全选**，勾上后按日志编号（`zmqbag_15` → 15）**从大到小**自动排好序（`z…15, 14, 13 …`），点“连续播放”就按这个顺序走；也勾选后每行会出现**序号**和 `▲▼` 按钮可微调，`/api/bag/playlist` 按传入顺序执行。一条播完自动加载下一条（含它自己的真实地图）。
- **轨迹不清零**：连续播放切换日志时，仿真实际走过的青色轨迹不清空，整段作业连在一起看。
- **导入文件夹**：填服务端绝对路径点“导入文件夹”，成功后会自动切到该文件夹并选中其中第一条日志，提示会保留几秒不被状态刷新覆盖。
- **取哪些数据**：位姿取 `base_pose`（缺省回退 `odom_data`，字段 3 → position/orientation 四元数），速度前馈取 `cmd_vel`；同时列出 bag 内所有话题与频率（`tf_dynamic` / `imu_data` / `obstaclecloud` / `whole_map` …）。
- **没有地图的日志**：部分日志（例如 `自动建图失败，车辆被困/`）的 `whole_map` 是空消息，说明当时没建出图；这类日志会切到 `map_import.build_open_field()` 造的**开阔场地**（无边界墙、无静态障碍，边长按轨迹跨度自动放大且不小于 26 m，充电桩/起点在正中），机器人不会被地图边界限制，面板会提示“该日志没有地图数据，已切换为不限制区域的开阔场地”。
- **路径加粗**：日志自带地图（说明当时在割草作业）时，地图上的日志轨迹（橙色虚线）与仿真实际走过的轨迹都会加粗、加深，作业走向更清楚；没有地图的日志保持细线。
- **日志图像窗口**：解析 `images` 表里的分割/调试图（优先 `GrassSegImg`，其次 `perception_debug_image` 等，JPEG 原始字节，180×153、约 6 Hz），回放时在地图右侧显示一个视频小窗（含帧序号与分辨率），只在载入日志时出现，普通建图/割草任务不显示；面板里显示“话题列表 / 地图 / 代价地图”等次要信息，统计口径压缩成两行。
- **播放 / 继续**：暂停（或拖过进度条）后“播放”按钮会变成 **继续**，点它从当前位置接着放；只有停止或回放结束后才是从头重播。暂停按钮在未播放时是禁用的。
- **面板布局**：日志播放只有两列——左边“日志文件”（最上面是播放栏，接着进度条、同一行的“当前日志 + 载入提示”、日志文件夹 + 刷新/图像窗口/独立窗口、全选、日志列表），右边“话题列表”+ 回放指标（吻合度、误差、时长、轨迹、地图、代价地图、位姿话题、电量）。
- **只看实际轨迹**：地图上不再画日志参考轨迹的虚线，只保留仿真机器人真正走过的青色轨迹；刚开始回放、换日志、拖动进度条时轨迹**从当前位置重新起笔**，不会出现从上一位置连到起点的那条"初始跳线"；只有回放中途真的发生重定位（相邻位姿跳变）时才补一段**红色细线**（`max(1.0, scale×0.008)`）连接。
- **话题屏蔽**：话题列表每一行前面有勾选框，勾掉即停止显示对应图层——`grid_costmap`（机器人周围那些红/橙小方块就是它：致命代价 ≥90 画红、≥50 画橙）、`base_pose`/`odom_data`（日志轨迹与仿真轨迹）、`perception_debug_image`（图像窗口）；`whole_map` 已作为仿真场地不可隐藏，其余话题只参与数据不单独绘制。勾选状态存 localStorage。
- **电量跟着日志走**：日志里有电量话题（`battery` / `battery_state` / `soc` 等关键字）就按其百分比显示，面板会标注“话题名（日志）”；没有电量话题时电量锁定 100% 不变，不会因为回放放电掉到低电量触发回充。
- **真实地图进仿真**：解析 `whole_map`（`OccupancyGrid`：字段 2 的 `map_info` 给出分辨率/宽高/原点，字段 3 是 0/100 栅格数据），用 `map_import.build_map_from_grid()` 直接生成仿真场地，地图名标为 `zmqbag·日志·实景`，日志地图从此就是仿真里那一块真实地形（36.1×22.95 m、0.05 m/格）；接口传 `{"name":…, "use_log_map": false}` 时只回放轨迹、不动当前地图。
- **真实代价地图叠加**：解析 `grid_costmap`（333×333 @0.03 m，0–100 代价，约 57 帧），界面用离屏 canvas 预渲染后叠加在地图上，红色=致命代价（≥90）、橙色=高代价（≥50）、浅蓝=低代价；栅格行 0 是最小 y，绘制时按负高度翻转，图例里有“日志代价地图”。
- **坐标系映射**：日志里的静态地图（`whole_map`）与位姿/代价地图常常不是同一坐标系（实测 `base_pose` 轨迹整体落在 `whole_map` 的占据区外，`tf_dynamic` 的 `world→base_link1` 又几乎不动），因此按各自语义分别处理——静态地图按自身 `origin` 换算，位姿轨迹整条**平移**（尺度不变）到日志地图自由区的中心，局部代价地图则按帧**跟随机器人**（以该帧对应的轨迹点为中心叠加）。这样机器人一定开在地图的可行驶区域内，代价地图也始终包住车身。
- **怎么“仿真”**：不是直接改写位姿，而是把日志当作定位真值，回放控制器按“参考速度前馈 + 位置/航向 P 修正 + 角速度阻尼”算 `v/w`，由四轮后驱差速运动学真的把车开出去（视觉、栅格、电量、里程都在跑）；日志里的**重定位跳变**（相邻采样位移 > 0.8 m）会同步对齐车体，计一次 `重定位`。
- **参考轨迹平滑**：`base_pose` 有约 1 kHz 时间戳抖动带来的航向噪声，载入时做 ±2 帧滑动平均，否则控制器会被噪声带着左右摆动。
- **吻合度**：每 0.1 s 采样一次日志位姿与仿真位姿的偏差，位置 ≤ 0.20 m 且航向 ≤ 12° 记为吻合，界面实时显示 **仿真吻合度 / 平均误差 / 最大误差 / 采样次数**。实测 4 个 bag（`data/bag` 下两个文件夹）：

| 日志 | 位姿帧 | 轨迹长 | 图像帧 | 仿真吻合度 | 平均误差 |
| --- | --- | --- | --- | --- | --- |
| `掉下台阶侧翻/zmqbag_14_2026-09-15` | 1028 | 32.5 m | 857 | **68.6%** | 0.17 m |
| `掉下台阶侧翻/zmqbag_15_2026-09-15` | 1054 | 33.3 m | 823 | **57.3%** | 0.21 m |
| `自动建图失败，车辆被困/zmqbag_1_2026-09-22` | 40000 | 2.2 m（原地被困） | 1601 | **100%** | 0.00 m |
| `自动建图失败，车辆被困/zmqbag_2_2026-09-22` | 36267 | 23.7 m | 1601 | **97.4%** | 0.06 m |

  “掉下台阶侧翻”两个日志里机器人是真的翻下台阶（相邻位姿有 6 次 >0.8 m 的跳变），平面四轮模型无法复现翻滚姿态，因此吻合度偏低，界面会把这类跳变计为“重定位”。

- **控制**：载入 / 播放 / 暂停 / 停止 / 拖动进度条跳转（跳转会先把车体放到该时刻的日志位姿）；回放倍速与顶部仿真倍速叠加。地图上用**橙色虚线**画出日志轨迹，青色渐隐轨迹是仿真机器人实际走过的路，两者重合度一眼可见。

### 四轮后驱模型

- 后轴左右轮差速驱动，前轮随动；运动学按后轴差速模型计算。
- 界面显示左右后轮线速度、线/角速度、航向与里程。
- 车体半径 0.18 m，割草宽度 0.44 m，视觉量程 1 m。

### 导入实景地图的尺度

真实地图默认按 **最大边长 40 m** 等比缩放（`POST /api/map/import` 可传 `max_extent` 覆盖）。早期默认 24 m 会把 45 m 的实景场地压到 24 m，走廊宽度小于车体直径，A* 会把区域切断；40 m 下窄道仍可通过。导入后充电桩与起点会按缩放后的米制留出 ≥0.55 m 离墙间隙。

## 界面模块

- 顶栏“主题”下拉框提供 **深色 / 浅色 / 暖色** 三种配色，选择保存在浏览器 localStorage；面板、按钮、地图画布（背景、网格、区域、路径、障碍）都会跟随切换。
- 顶栏“仿真”下拉框用于在两套独立仿真应用之间切换：切换会整页刷新到目标应用（详见上文「两种独立仿真应用」）。
- 顶部“模块”菜单可显示/隐藏遥测、手动控制、区域覆盖、事件日志、参数设置。
- 右上角 **退出** 按钮：二次确认后停止当前任务（不保存断点）、关闭后端服务并释放端口，界面整屏切到「控制台已退出」，并自动尝试关闭标签页、把标题改成「已退出 · 机器人控制台」。
  - 浏览器只允许脚本关闭「由脚本打开」的窗口，地址栏直接打开的标签页会被拒绝；被拒绝时页面会显示提示，按 `Ctrl` + `W`（macOS `⌘` + `W`）或点标签页的 × 即可关闭，服务端此时已经停止、端口已释放。
- 各非核心面板标题左侧有 `⋮⋮` 拖动手柄，可自由拖动位置；布局与显示状态保存在浏览器 localStorage。
- **任务操作栏可收起**：工作区顶部的“任务操作”行（地图 / 模式 / 自动建图 / 割草 / 回充 / 倍速 / 进度）右上角有“收起 / 展开”按钮，收起后只剩标题行，把竖直空间让给地图；状态记忆在 localStorage（`mowerMissionFoldedV1`）。
- **手动控制面板的两个参数是“键盘档位”**：`线速度 (m/s)`（0.10–0.60）与 `角速度 (rad/s)`（0.20–1.80）只决定按 **▲/W、▼/S、◀/A、▶/D**（或点屏幕方向键）时机器走多快、转多快，**不会自己让机器动起来**；数值随输入即时生效并记在 localStorage。按下时后端收到 `{"command":"forward","linear":0.30,"angular":0.50}` 这类带幅值的指令，方向仍由指令决定（正角速度=左转），幅值取输入框的值（超限夹到 0.60 / 1.80）。脚本仍可直接用 `{"command":"drive","linear":…,"angular":…}` 连续下发线/角速度。手动控制会中止当前自动任务。
- **参数**面板为参数主界面，内部分为两个子页签，页签选择会记忆到 localStorage：
  - **机器人实体**：车体半径、割草宽度、最大速度、充电桩半径、弓字间距、边缘内缩、沿边速度、内直角前移、绕障余量，以及“电源”分组（低电回充、恢复电量、耗电系数）。
  - **传感器**：视觉 FOV、视觉量程、视觉射线数（对应“参数 / 传感器 / 视觉”三级结构）。
  - 地图相关的功能已从参数面板移出，独立成侧栏的 **地图** 面板（地图导入 / 地图编辑）。最小区块面积、大型障碍阈值不再放在界面上，仍可用 `config.configure(min_zone_area=…, large_obstacle_area=…)` 或 `tests/params.py` 调整。
- **底部面板**固定在界面最下方，标题栏提供 **事件日志 / 日志播放** 两个页签，可切换显示：事件日志页签显示条数；日志播放页签为 bag 回放界面。右侧按钮可在“收起/展开”之间切换；整个底部面板受“模块”菜单的“底部面板”开关控制。
- **地图功能在侧栏**：独立面板，含两个可收起分组 **地图导入** / **地图编辑**（原“当前地图微调”分组已取消，运行时改图统一走编辑器：载入当前地图 → 改 → 保存为新图），可用“模块”菜单里的“地图功能”开关整体显示/隐藏。
- **首次进入界面全部收起**：第一次打开（localStorage 里没有布局记录）时，侧栏各面板、底部面板与任务操作栏都是收起状态，把竖向空间留给地图画布；之后的展开/收起状态会记住。
- **地图编辑期间禁止开任务**：`POST /api/task` 在草稿未保存/未退出时返回 400“地图编辑中：请先保存地图或取消编辑，再开始任务”，编辑按钮也会随任务状态置灰；保存或退出编辑后自动恢复。
- 地图上的场地边界线沿场地多边形向外偏移 0.12 m 绘制（沿用原来的边界线配色）：建图得到的占据栅格是“可达点”，边界线画在可达区外侧，不会盖住可割区域。
- 任务栏中显示边界建图、总覆盖（两位小数）、总路程（整数 m）、任务时长（整数 mm:ss）；运行里程和运行时长也按整数显示。

### A/B 整图效率基准

cd robot_simulation
