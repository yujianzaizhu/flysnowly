# 视觉割草机器人控制台

四轮后驱割草机器人仿真系统：以 **100° FOV / 1 m 视觉深度传感器**为主要感知，完成自动建图、自动分区、自动割草（沿边 + 弓字全覆盖 + 绕障）、自动回充与断点续作，并通过浏览器界面实时展示地图、覆盖情况、视觉视场和任务状态。

后端零第三方依赖，要求 Python 3.8+。

## 快速开始

```bash
cd robot
./run.sh                 # 默认 http://127.0.0.1:8000/
# 或指定地址与端口
HOST=0.0.0.0 PORT=9000 ./run.sh
# 也可以直接运行
python3 backend/server.py --host 127.0.0.1 --port 8000
```

打开 <http://127.0.0.1:8000/>：

1. 在顶部 **地图** 下拉框选择 1–5 号场地（切换会重建机器人与地图）。
2. 点击 **自动建图**，机器人驶向边界并逆时针巡边；完成后自动分区并返回充电桩。
3. 在 **割草区域** 输入顺序（留空时自动使用全部区域，如 `1,2,4,5`），点击 **开始割草**。
4. 需要中途补电时点击 **立即回充**；充好电后点击 **继续任务**，机器人会先回到断点再继续。
5. 仿真速度支持 1x / 2x / 4x / 8x / 16x / 32x，便于快速演示完整任务。
6. 在 **参数 → 地图** 页签点击“选择文件”或“选择目录”导入真实 PGM 地图；导入后立即切换为新增的模拟场地。

### 导入真实 PGM 地图

“参数 → 地图”页签提供两种真实地图导入方式（界面不再提供服务端路径输入和最大边长设置）：

- **选择文件**：支持 `.pgm`（必需），以及 `default.json`、`map_info.json`、`.yaml/.yml`（可选）；`default.json` 会自动放到 `path/default.json`。
- **选择目录**：自动保留目录内的 `path/` 结构，适合直接选择包含 `grid_map.pgm` 和 `path/default.json` 的地图目录。

浏览器选择文件时使用 `POST /api/map/upload` 上传，服务端只接受 `.pgm/.json/.yaml/.yml`，单文件最大 16 MB，单次总量最大 24 MB；未指定时地图按默认 24 m 最大边长等比缩放。服务端仍保留 `POST /api/map/import`（服务端路径导入）供脚本/测试使用。

- 解析 `default.json` 的 `resolution`，读取 P5/P2 PGM，提取最大连通自由区的外轮廓和内部障碍孔洞。
- 地图会等比缩放到 `max_extent`（默认 24 m，避免真实几十米场地在仿真中过大），并自动生成充电桩/起点。
- 导入地图会加入地图下拉框（编号从 101 开始）；同一来源重复导入会覆盖原编号。界面会把真实障碍轮廓画成实线，视觉聚类结果仍以虚线显示。
- 地图下拉框旁提供“删除地图”按钮，仅删除导入地图；删除当前地图后自动切回 1 号内置场地。内置地图不可删除。

### 地图编辑（静态障碍 / 动态障碍 / 禁区）

“参数 → 地图”页签的 **地图编辑** 分组可以在运行时给当前地图添加对象，编辑结果按地图分别保存。**只有在建图完成后、且没有任务运行时才能编辑**（否则界面按钮置灰、接口返回 400），重新建图会自动清空当前地图上的障碍物与禁区：

- **添加静态障碍**：点按钮后在地图上点击放置，写入真实几何——视觉射线可探测、底盘可碰撞，等同于原本的场地障碍物；半径由“编辑半径”控制（0.12–1.50 m）。
- **添加动态障碍**：同样点击放置，生成一个沿“动态行程”长度两点往返巡逻的圆柱障碍（默认速度 **0.15 m/s**），界面上用白色虚线轨迹表示巡逻范围；视觉与碰撞都按实时位置计算。列表里的“编辑路径”可以重新指定巡逻起点 A 与终点 B（地图上点两下，带虚线预览）。
- **添加禁区**：选“添加禁区”后在地图上 **按住左键拖出矩形**（拖拽过程中实时预览尺寸），松开即写入。禁区只写入导航/割草膨胀层（`blocked` / `mow_blocked`），机器人不进入、刀盘不切割，但视觉仍把它当作空地（不进入占据栅格）；区域覆盖率目标会自动扣除不可达面积，不会因为禁区而永远达不到完成条件。
- 每个对象都会列在编辑区下方（类型、编号、坐标；禁区显示为两个对角点；动态障碍显示 A→B 路径），右侧“删除”单独移除，“清空编辑”一次性清空当前地图的所有编辑对象。
- 地图上会给编辑对象标注 **#序号**（禁区同时标注“禁区 #n”），便于和列表一一对应。
- 边界之外的点击会被服务端拒绝（400），避免把对象放到墙外；编辑对象按地图 id 存储，切换地图后仍保留，**重新建图会清空当前地图的编辑对象**。
- **禁区不可进入**：禁区会写进栅格 `blocked`/`mow_blocked`（规划层绕开），同时在沿边、弓字、绕障等反应式阶段加了一层前向保护（`_guard_no_go`），目标点或前方 0.2–0.45 m 落进禁区就停车转向，实测割草全程 0 次进入禁区。
- **A 模式绕禁区**：沿边途中前方被禁区挡住时，按“绕障碍物”的方式逆时针沿禁区外扩 `ring_margin` 的矩形走半圈，直接衔接到禁区出口之后的边缘点继续沿边（`no_go_ring` 阶段，25 s 超时保护）；弓字线遇到禁区则跳过该段并重新规划剩余区域。
- **B 模式禁区膨胀**：B 模式先排弓字线，禁区会额外膨胀 0.28 m（A 模式 0.10 m）写入 `mow_blocked`，弓字线与禁区边缘留出余量，不会贴着禁区边缘卡住。
- **沿边同时受区域与地图边界约束**（`_combine_edge_bounds`）：只用区域外接框（外扩 0.5 m）内的边缘点，避免沿到相邻区域；离场地外墙不足 车体半径 + 0.10 m 的点会沿指向区域中心的方向内移，巡边安全带也按同一余量筛选。

### 地图缩放与坐标

- 充电桩默认半径 0.70 m（可通过 `dock_radius` 参数调整），机器人起点会优先选择离场地边界更远的自由栅格。
- 地图支持鼠标滚轮缩放、左键拖动平移、双击复位，也可使用地图左上角的 `＋ / － / ⤢` 按钮。
- 鼠标在地图上移动时显示当前世界坐标（单位 m），便于核对导入地图形状和路径位置。

## 功能说明

### 视觉传感器

- 100° 视场角（±50°），41 束深度射线，量程 1 m。
- 每束光线同时用于避障/沿边控制和占据栅格建图。
- 界面中的蓝色扇面即实时视觉视场，颜色随距离变化。

### 自动建图

- 从当前位置出发，向前行驶直到视觉发现外墙。
- 以 **墙体在右侧** 的沿边控制逆时针绕场一周，视觉持续写入栅格地图（空闲/占据）。
- **孤岛识别**：巡边中若形成面积小于 8 m² 且闭环内部存在已探明占据栅格的闭环，才判定为障碍物孤岛；外凸半岛/顶部尖角造成的路径自接近不会误触发脱离，沿边会继续直到真正的外墙闭环。已识别孤岛会记录并在后续搜索中避开。
- 当闭环面积达到 12 m² 以上才判定建图完成，自动执行自由区漫游与分区，返回充电桩并停靠充电。
- 建图过程中电量低于 **30%**：保存断点 → 回充 → 电量高于 **80%** → 返回断点并对齐航向继续巡边。
- 巡边被障碍物/狭窄角卡住时，优先沿最近约 1 m 的历史轨迹倒车脱困，再重新寻找外墙；历史脱困失败才使用远离碰撞方向的脱离策略。
- **建图只做一次**：建图完成后写入完成标记并丢弃巡边进度与巡边断点；之后若回充/继续任务/脱困又把状态恢复到巡边，会直接回桩收尾，不会再次绕场建图（避免“建图→回桩→继续建图”反复循环）。

### 运行性能

- 视觉写入栅格改为按 0.1 m 栅格采样，避免同一栅格被 0.05 m 间隔重复写入。
- 预计算外墙/障碍物线段用于射线检测；区域安全巡边带使用多源 BFS 距离变换，并缓存同一区域的沿边路线。
- 障碍物聚类、边界建图进度按占据数据版本缓存，界面状态刷新只重新编码变化的数据。
- 动态障碍物只刷新圆形占据（`_refresh_dynamic_geometry`），静态障碍轮廓/线段不再每帧重算；`/api/state` 里的场地静态描述（边界、障碍轮廓、地图列表）也做了版本缓存。实测加入动态障碍前后 32x 仿真推进速率基本一致（33.4x vs 33.8x）。
- **倍速卡顿优化**（内置图单 tick 3.34 ms → 0.63 ms；导入实景图 2.34 ms → 0.89 ms）：
  - 占据/膨胀写入改为**按行切片**（`GridMap._fill_rows`）：原来每次 `mark_occupied` 要逐格写 9×(5×5+5×5) 约 450 格，现在等价地写 3 个方块（覆盖/导航膨胀/割草膨胀），实测 `update_from_scan` 从 1.56 ms/tick 降到 0.13 ms。
  - `world.raycast` 内联线段/圆求交、提前剪枝，41 条射线的扫描从 0.76 ms/tick 降到 0.33 ms。
  - 沿边超时用的路径长度按 `(点数,首点,末点)` 缓存，不再每 tick 求和。
  - **自适应积分步长**：≤4x 用 20 ms、≤16x 用 33 ms、>16x 用 50 ms，配合每轮最多 4 步的补帧上限，32x 实测可达 31.6–32.0x（优化前只有约 3x 推进）。
  - 前端在高倍速下每 4 次轮询才取一次栅格位图（`GET /api/state?map=0` 跳过 71 KB 的 occupancy/mowed），地图位图在后端按 `grid.version` 缓存。
  - **线段空间索引**：外墙/障碍物线段按 1.5 m 方格分桶（`world._rebuild_segment_index`），`raycast` 与 `boundary_distance` 只遍历机器人附近桶内的线段。导入实景图外墙有 100+ 段时，单次扫描从 1.65 ms 降到 0.30 ms。
  - 建图闭环判定改用 0.3 m 空间哈希（`_map_hash`）查同位置历史点，不再每 tick 线性扫描整条巡边路径（路径几千点时是主要开销）。
  - 自由区采样内联步进（去掉每条射线每格的函数调用）；`region_manager` 的 OccupancyGrid 发布改为按真实时间 1 s 节流（原来按仿真时间 2 s，32x 下等于每帧发布一次 97k 点栅格）。
  - 实测（map_1 实景，单核）：32x 档实际推进 **28.0x**（优化前约 3x）、16x→13.8x、8x→7.3x、4x→3.7x；建图阶段 14.6x；32x 割草完成覆盖 97.2%、碰撞 0。
- 障碍物轮廓在世界切换时预计算，避免每次 `/api/state` 重复计算。

### 自动分区

- 建图完成后先按探明自由区做 **连通域分区**，不再以整张地图的包围盒做 BSP 切分。
- **每次开始割草重置障碍层**：建图完成时记录当时的占据/膨胀栅格作为基线；新割草任务先恢复到该基线，清掉上次割草涂抹出来的障碍（假障碍、草地碎屑误检），场地边界建图与分区轮廓保持不变。
- 连通域形状较规则（凸包实心度 ≥ 0.90）时整体作为一个区域；哑铃形/狭窄连接的区域才沿最远点测地线切成两个区域。
- 区域栅格**互不重叠**（每个格子只归属一个区域），对外输出 `outline` 实际栅格轮廓，界面按真实轮廓绘制，不再用外接矩形，避免相邻区域看起来重叠；`zone_at()` 只按归属栅格判断，不再用外接矩形回退，覆盖率统计不会串区。
- 所有区域面积不低于 **20 m²**；小于该面积的碎片合并到最近的连通区域。
- 每个区域的 `free`、包围盒和覆盖率会显示在控制台；区域编号按质心从上到下、从左到右排列。

### 自动割草（A / B 两种模式）

- 启动时确认区域顺序（留空则使用全部区域），按顺序前往各区域。
- **A 模式（默认，先沿边）**：每个区域流程：
  1. 沿区域边缘一周；
  2. 弓字覆盖；
  3. 纵向补割；
  4. 环形补割。
- **B 模式（先弓字）**：每个区域流程：
  1. 先规划弓字覆盖；
  2. 遇到**大型障碍物**：不绕障，直接掉头并重新规划剩余弓字；
  3. 遇到**小型障碍物**：绕障后继续弓字；
  4. 弓字和纵向补割完成后，再沿区域边缘割草一次。
- 控制台顶部可以选择 A/B 模式；模式会随任务保存，回充续作后保持。
- A 模式详细流程：
  1. **沿区域边缘一周**：规则区域使用内缩矩形；不规则区域沿**实际自由区/区域边界**生成巡边路径；区域内部障碍物由后续环形补割按障碍物实体边界处理。路径中心保持约一个车体半径的墙体安全间距，同时让 0.44 m 刀盘覆盖到边界最后一小条草。沿边采用当前路径段上的 0.30 m 纯跟踪预瞄；外凸半岛/墙体命中不会被误判为场内障碍物，避免跳过整段边缘。
  2. **弓字覆盖**：按 0.30 m 行距对区域内尚未割草的连通部分生成蛇形线段，逐段巡迹；只规划可割草且未割过的连续段。
  3. **纵向补割**：横向弓字结束后若覆盖率仍不足，生成纵向弓字补割。
  4. **环形补割**：对区域内已发现且未绕行过的障碍物绕行一周，覆盖障碍物周围区域。
- **弓字顺序优化**：所有弓字段按“当前位置 + 航向 + 就近端点”重排；障碍物把一条弓字切成两段时，先完成当前一侧，再前往另一侧，减少来回穿越。
- **漏扫补扫与覆盖率保护**：区域主流程完成后检查未割草连通块；面积约 0.2–9 m² 的漏扫块会生成补扫弓字（或沿长轴直扫），最多连续两轮补扫，清掉第一轮剩下的窄条与边角。若覆盖率仍明显低于实际可达目标，会再规划一次剩余连通域，不会因连续碰撞或局部不可达直接结束区域。
- **内外直角差异化补扫**：逆时针沿边时，外凸直角由预瞄自然转过，不再执行前进-后退；内凹直角则沿入射方向多前进 `inner_corner_advance`（默认 0.16 m）到尖角后再后退转向，覆盖内直角尖尖处的小块漏扫。沿边速度由 `edge_speed`（默认 0.50 m/s）单独控制，沿边超时按实际路径长度动态计算，回充后不会因旧的 90 s 固定超时直接跳过剩余沿边。
- **区域边界约束**：沿边采用逆时针方向，绕障也按逆时针；绕障路径只使用区域内的连续弧段，触到区域边界时结束绕行并沿区域边缘继续，不会绕到其他区域。
- **沿边绕障续接**：沿边遇到已探明或未聚类的小障碍时，先逆时针绕行；绕完或到达区域边界后，重新选择障碍后的边缘点继续沿边。B 模式的最终沿边不会再因为边缘附近的障碍命中而整段跳过。
- **后退脱困**：沿边/弓字/绕障/前往区域时若持续 4 s 没有有效位移，机器人会沿最近约 1 m 的历史轨迹倒车脱困，再恢复原阶段；同一区域最多尝试 3 次，避免长时间困在障碍物间。
- **不可达目标处理**：导航前若目标点被新探明障碍覆盖，会改去当前位置连通域内最近的可达点；弓字段起点被覆盖时自动沿弓字寻找第一个可通行入口，若该端被堵则从线段另一端进入，只有两端都不可达才丢弃该段。若区域沿边入口全部不可达但区域内部仍有可达点，会从该内部点开始清扫剩余可达弓字线；只有整个区域都没有可达入口时才跳过该区域。导航中目标栅格被障碍覆盖会立即重规划，而不是继续顶住或直接结束区域。
- **失败弓字按计划键记录**：不可达/卡住/绕障中断等失败都按规划弓字线 `(起点, 终点)` 记录（而不是实际进入点），所以同一条被堵弓字线不会在每一轮重规划里反复重试，剩余可达弓字线可在同一区域内补完，避免“少一块”。
- **节点连续不可达自动放开膨胀**：节点侧规划（planner / dock）连续 5 次找不到可达目标时，会临时放开起点与目标周边 1.2 m 的障碍膨胀再试，并改走最近可达点，模拟视觉碎片把通道封死的情况。
- **高速显示优化**：仿真速度 ≥4x 时前端状态轮询提升到 50 ms，并同步缩短位姿插值窗口，减少高速下的跳跃/卡帧。
- **A 模式沿边绕障续接**：沿边被障碍物中断并完成绕障后，会选择机器人附近、避开障碍且直线/ A* 可达的边缘点继续大沿边；不会直接跳到弓字阶段。
- **贴边绕障**：绕障半径根据视觉占据栅格沿视线方向的实际外边界自适应，不再固定走理想圆；默认安全余量约 0.34 m（含栅格膨胀约 0.1 m），较上一版缩小，可通过窄通道。
- **视觉盲区花瓣绕障**：小型障碍物绕行中若连续失去视觉接触，机器人会停下并向障碍物方向旋转探明，再继续绕行。
- 巡迹遇障：**只使用视觉建图得到的占据栅格**聚类障碍物，不读取场地真值；拟合出包围圆并按 **估算面积** 分类：面积 ≥ **5 m²** 记为大型（B 模式掉头用），**小于 5 m² 一律视为小型**（绕障 + 花瓣探明）。阈值可在“参数 → 地图 → 大型障碍阈值 (m²)”调整。
- **界面真实边界**：控制台同时绘制场地障碍物的真实轮廓（**白色实线**，外侧加深色描边以便在浅色主题下也清晰）和机器人视觉聚类得到的大小障碍估计（橙/黄色虚线），便于对比感知结果。
- **不二次绕障**：成功绕过（或确认无法绕行）的障碍物会加入已绕行记录；再次遇到同一障碍物时跳过环形动作，直接重新规划路径。该记录在回充/断点续作后仍保留。
- 若环形绕障过程中发生碰撞或受阻，机器人会记录该障碍物并退出绕行，避免反复撞击。
- 覆盖率 = 已割草空闲栅格 / 区域空闲栅格；受车体半径与割草宽度限制，障碍物周围和墙边会保留少量未覆盖。典型覆盖率 85%–96%。
- 一个区域完成后自动前往下一个区域；全部完成后返回充电桩。

### 任务完成指标

任务回到充电桩结束时，事件日志会补两行汇总（`_log_task_summary`）：

- 建图任务：`建图指标 · 边界建图 95.2% · 自动分区 2 个（区域1 175.5 m²；区域2 160.6 m²）`
- 割草任务：`割草指标 · 总覆盖 97.84%（区域1 97.8%（…/… 格））`
- 通用指标：`里程 637 m · 时长 33:16 · 弓字线段 642 段 · 绕障 5 次 · 脱困 5 次 · 回充 4 次 · 碰撞 12 次 · 平均无碰撞里程 53.1 m`

### 自动 / 手动回充与断点续作

- 割草中电量低于 30%：自动保存任务（相位、区域、边缘进度、弓字区域、已绕障碍、断点位姿、沿边已用时间）→ 返回充电桩 → 充到 80% → 返回断点 → 恢复任务。
- 默认耗电速率为改造前的 **60%**，可通过参数 `battery_drain_factor`（默认 0.6）调整。
- 机器人原地待机（线速度、角速度均为 0）时，耗电按正常行驶功耗的 **10%** 计（`IDLE_DRAIN_SCALE = 0.1`），停靠充电桩仍按 8 %/s 充电。
- “停止任务”是暂停语义；暂停/回充时间不计入沿边 90 s 超时，继续任务不会因暂停过久而直接结束沿边。
- 控制台点击 **立即回充**：保存任务和割草记录，返回充电桩；**不会**自动恢复，必须点击 **继续任务**。
- 续作前机器人先驶回保存的断点；建图任务还会原地对齐到断点航向，保证继续逆时针巡边。
- 断点保存在当前任务内，切换地图或复位会清除。

### 四轮后驱模型

- 后轴左右轮差速驱动，前轮随动；运动学按后轴差速模型计算。
- 界面显示左右后轮线速度、线/角速度、航向与里程。
- 车体半径 0.18 m，割草宽度 0.44 m，视觉量程 1 m。

### 节点仿真开关

“导航节点”面板顶部提供 **节点仿真** 开关（`POST /api/nav/mode {"enabled":true|false}`）：

| 状态 | 规划 | 速度指令 | 适用 |
| --- | --- | --- | --- |
| 勾选（默认） | `nav_task_action` / `visual_egway_action` / `autodock_action` 等动作服务输出的话题 | 节点 `command()` 计算并发布 `cmd_vel`（纯跟踪控制律在节点内） | 验证节点接口与节点参与仿真 |
| 取消 | 全部使用仿真内置算法（原 `grid.plan` / `lane_segments` / `edge_route`） | 仿真底盘产生 `cmd_vel`（发布者 `sim`） | 对照/回退，排查节点问题 |

关闭后节点仍然在线（心跳、输入话题、快照照常），只是不再参与规划与控制；`GET /api/nav` 的 `enabled` 字段表示当前状态，`cmd_vel` 话题的发布者可区分 `planner` / `dock` / `sim`。

### 输入输出链路

| 方向 | 话题 | 说明 |
| --- | --- | --- |
| 仿真 → 节点 | `fuse_pose_3d` / `combined` / `imu_data` / `tf_dynamic` / `odom_hardware_signal` / `is_edgeway` / `region_area` / `whole_map` / `area_map` | 10 Hz 位姿、IMU、TF、碰撞/急停、沿边标志、区域面积、地图元信息 |
| 节点 → 仿真 | `cmd_vel` | 节点模式下由当前活动节点（planner / dock）按纯跟踪律计算并发布，仿真底盘执行；系统算法模式下由 `sim` 发布 |
| planner → 仿真 | `task_plan_path`（Path）、`nav_task_path`（PathWithIndex）、`follow_task_path`、`current_path_index`、`nav_status` | 点到点/覆盖/沿边/重割规划结果，TaskManager 直接消费这些话题 |
| dock → 仿真 | `egway_poses`（视觉沿边路径）、`global_plan`、`recharge_start_pose`、`global_pose` / `current_pose`、`nav_error_pub`、`nav_status` | 沿边与回充路径、回充起始位姿 |

### 任务模式映射

| 仿真动作 | 使用接口 |
| --- | --- |
| 导航/弓字/沿边的速度指令 | planner/dock 节点 `command()`：按位姿与目标点计算 `(v, w)` 并发布 `cmd_vel` |
| 前往区域/弓字起点/断点导航 | planner `nav_task_action`，`mode=NAVIGATION(10)` → `task_plan_path` |
| 弓字全覆盖 | planner `nav_task_action`，`mode=COVERAGE(30)` + `bow_type` → `nav_task_path` |
| 小块漏扫补割 | planner `nav_task_action`，`mode=OVERLAPING(50)` → `nav_task_path` |
| 区域沿边（A 模式首圈、B 模式收尾、绕障后继续） | dock `visual_egway_action` → `egway_poses` |
| 区域边界规划（供外部/对照） | planner `nav_task_action`，`mode=BOUNDARY(40)` |
| 返回充电桩（低电、手动、任务结束） | dock `autodock_action` → `global_plan` + `recharge_start_pose` |
| 充满后离桩续作 | dock `leave_dock_action` → `global_plan` |

动作服务遵循文档的受理规则：运行中重复 `START` 返回 `REJECTED`（暂停中返回 `SUCCEED` 并继续）；`PAUSE` / `CONTINUE` / `CANCEL` / `FINISHED` 分别置暂停、继续、抢占、结束；未知 cmd 返回 `UNSUPPORTED`，任务结束/抢占/异常分别发布 `SUCCEEDED` / `PREEMPTED` / `ABORTED` 结果。控制台“停止任务 / 继续任务”会同步给 planner 节点 PAUSE / CONTINUE。

### static_config 参数导入

服务启动时会自动解析 `<repo>/data/static_config`（可用环境变量 `FIBOT_STATIC_CONFIG` 指定其它目录），也可以在界面点“导入 static_config”或调用接口：

```bash
curl http://127.0.0.1:8000/api/nav/config                       # 查看已导入的参数
curl -X POST http://127.0.0.1:8000/api/nav/config -d '{}' -H 'Content-Type: application/json'
curl -X POST http://127.0.0.1:8000/api/nav/config -d '{"path":"/path/to/static_config"}' -H 'Content-Type: application/json'
```

解析的文件与用途：

| 文件 | 抽取内容 |
| --- | --- |
| `zmq_comm_name.yaml` | 话题/服务/动作名称与端口（189 话题、28 服务、12 动作），用于核对与展示节点接口 |
| `rk3576_robot_nav_params_ins.yaml` | 弓字速度 `state_bow_straight_vel`、视觉沿边速度 `state_vis_egway_straight_vel`、避障距离、回充观察距离、脱困次数、车体尺寸 |
| `rk3576_local_planner_params.yaml` | DWA 速度上限、到点容差 `xy_goal_tolerance`/`yaw_goal_tolerance`、`edge_task_vel`/`coverage_task_vel`、`path_width` |
| `ipa_coverage_planning_server.yaml` / `ipa_room_exploration_server.yaml` | 覆盖/沿边规划半径、`shrink_distance`、`grid_obstacle_offset`、`min_cell_area`、`path_eps` |
| `region_manager.yaml` | `dilate_size`、`path_dilate_size`、`visual_edge_dilate_size` 等膨胀半径 |
| `trajectory_map_generator.yaml` | 建图记录间距 `distance_interval`（用于 `record_path POINT` 抽点）、帧名 |

映射到仿真配置（`config.settings`）的是速度类参数：`nav_speed`、`mow_speed`、`edge_speed`；DWA 的速度上限作为**节点控制上限**生效（`command()` 内钳制），不会降低底盘能力——否则建图/脱困转向不足会撞墙。其余参数保存在 `/api/nav` 的 `static_config.params` 中供查看与后续扩展。

### 导入实景地图的尺度

真实地图默认按 **最大边长 40 m** 等比缩放（`POST /api/map/import` 可传 `max_extent` 覆盖）。早期默认 24 m 会把 45 m 的实景场地压到 24 m，走廊宽度小于车体直径，A* 会把区域切断；40 m 下窄道仍可通过。导入后充电桩与起点会按缩放后的米制留出 ≥0.55 m 离墙间隙。

### 通过 HTTP 驱动节点

```bash
# planner 覆盖任务（path_name 即区域顺序，等价于界面“开始割草”）
curl -X POST http://127.0.0.1:8000/api/nav/action -H 'Content-Type: application/json' \
  -d '{"node":"planner","action":"nav_task_action","cmd":1,"goal":{"mode":30,"path_name":"1,2"}}'

# dock 立即回充
curl -X POST http://127.0.0.1:8000/api/nav/action -H 'Content-Type: application/json' \
  -d '{"node":"dock","action":"autodock_action","cmd":1,"goal":{"docking_waypoint":"dock"}}'

# 查询节点与话题状态
curl http://127.0.0.1:8000/api/nav | python3 -m json.tool | head -40
```

`cmd` 取值：1 START、2 CANCEL、3 PAUSE、4 CONTINUE、5 FINISHED。前端“导航节点”面板实时展示两个节点的心跳、动作状态与话题计数。

> 建图的“走一圈”运动仍由仿真建图状态机执行（对应真实系统的地图采集动作），但**记录、保存、装载、分区**全部走 `trajectory_map` / `region_manager` 节点；`map_load` 在节点内部调用 `build_free_area` + `partition_zones` 生成区域并通过 `map_info`/`area_map` 发布。

## 参数设置（外部参数入口）

测试与二次开发统一使用 [tests/params.py](tests/params.py)：

```python
from tests import params

params.ROBOT_PARAMS.update({"robot_radius": 0.22, "vision_range": 1.4, "vision_rays": 61})
params.BATTERY_PARAMS.update({"battery_low": 25.0, "battery_resume": 75.0})
params.MOWING_PARAMS.update({"mowing_mode": "B", "lane_spacing": 0.28, "ring_margin": 0.50})
params.apply_params()          # 立即应用到 world / robot_car / planner / tasks / grid_map
params.reset_params()          # 恢复默认值
```

可配置项包括车体半径/割草宽度/轮距、最大速度、视觉 FOV/量程/射线数、低电与恢复阈值、充电速率、耗电系数、A/B 模式、边缘内缩、沿边速度、内直角前移、弓字间距、绕障余量、最小区块面积、大小障碍物分类阈值等。生产环境也可以通过 `backend/config.py` 的 `configure(...)` 使用同一套配置。

## 界面模块

- 顶栏“主题”下拉框提供 **深色 / 浅色 / 暖色** 三种配色，选择保存在浏览器 localStorage；面板、按钮、地图画布（背景、网格、区域、路径、障碍）都会跟随切换。
- 顶部“模块”菜单可显示/隐藏遥测、手动控制、区域覆盖、事件日志、参数设置、导航节点。
- 各非核心面板标题左侧有 `⋮⋮` 拖动手柄，可自由拖动位置；布局与显示状态保存在浏览器 localStorage。
- **参数**面板为参数主界面，内部分为三个子页签，页签选择会记忆到 localStorage：
  - **机器人实体**：车体半径、割草宽度、最大速度、充电桩半径、弓字间距、边缘内缩、沿边速度、内直角前移、绕障余量，以及“电源”分组（低电回充、恢复电量、耗电系数）。
  - **传感器**：视觉 FOV、视觉量程、视觉射线数（对应“参数 / 传感器 / 视觉”三级结构）。
  - **地图**：最小区块面积、大型障碍阈值，地图编辑（添加静态障碍 / 动态障碍 / 禁区，含半径、动态行程、删除与清空），以及真实 PGM 地图的选择文件/选择目录导入入口。
- **底部面板**固定在界面最下方，标题栏提供 **事件日志 / 导航节点** 两个页签，可切换显示：事件日志页签显示条数；导航节点页签为三列布局（节点状态 | static_config 参数 | 话题列表），顶部一行放节点仿真开关与 static_config 导入，窄屏（<620 px）自动回落为单列。右侧按钮可在“收起/展开”之间切换；整个底部面板受“模块”菜单的“底部面板”开关控制，“导航节点”开关等价于切到导航节点页签。
- 地图上的场地边界线沿场地多边形向外偏移 0.12 m 绘制（沿用原来的边界线配色）：建图得到的占据栅格是“可达点”，边界线画在可达区外侧，不会盖住可割区域。
- 任务栏中显示边界建图、总覆盖（两位小数）、总路程（整数 m）、任务时长（整数 mm:ss）；运行里程和运行时长也按整数显示。

### A/B 整图效率基准

`tests/benchmark_modes.py` 会对 5 张地图分别执行起点附近随机开阔位置、随机区域顺序的整图割草任务，A/B 两种模式使用相同起点和顺序。默认 11 次 × 5 图 × 2 模式 = **110 次整图试验**，并输出成功率、平均/中位/P95 时长、平均路程、平均覆盖率和碰撞统计。

```bash
cd robot
python3 tests/benchmark_modes.py --trials 11 --workers 8
```

结果保存到 `/tmp/mode_benchmark_full.json`。

`tests/benchmark_single_zone.py` 保留了早期单区域快速对比脚本。
